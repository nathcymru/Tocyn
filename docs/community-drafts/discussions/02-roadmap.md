# Help shape Tocyn's first milestones

The initial direction is:

- v0.1.0: repository and security foundations, consistent coding standards, and FidesLang across the majority of applicable application code.
- v0.2.0: a whole-codebase FidesLang review, complete applicable coverage, and optional end-user capabilities.
- v0.3.0: replace Resend with Cloudflare-native email.

The public project's standalone contact form is separate from the application email migration.

I would particularly value practical input on tenant boundaries, contributor setup and how the optional privacy tooling should be presented to people running their own deployment.

What deployment scenario would you use Tocyn for? Which requirement would determine whether you could try an early release? Please include the problem and intended outcome; we can turn agreed work into scoped issues.

These are intended outcomes, not a commitment to dates.
