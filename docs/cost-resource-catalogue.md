## Accounting assumptions

Amounts are resource quantities, not currency. If a provider publishes fractional units, adapters round conservative reservations upward into the named integer unit; actual billing may apply further rounding. Never silently change a dimension's unit without a schema/catalogue version change.

For a daily dimension, a synthetic example is `[2026-09-10T00:00:00Z, 2026-09-11T00:00:00Z)`. A paid monthly window instead uses the verified account renewal timestamps. Logs, trace exports and external providers may have different boundaries; do not use one global reset timer. Stock ceilings carry forward across both.

A 100-unit declared available allocation provides 80 new-work units and 20 recovery units by default. For Queue work estimated at five operations per bounded message, that permits at most sixteen new-work envelopes before accounting for additional Queue overhead; the limiting dimension across the complete flow may permit fewer. This is arithmetic on a synthetic allocation, not a measured production throughput claim. Budget authority, notifications, journal retries and observability consume resources too.

## Current application diagnostic envelope (#159)

The existing `logEvents`/`traceEvents` dimensions are reused by `estimateDiagnosticEnvelope` in `apps/server/src/observability/resource-envelope.ts`. For trusted workload bounds H HTTP requests and C independent resource compositions, the current emitters require an upper-bound envelope of **H + A + M + 64 × C log events**, with **zero trace events** because no trace transport is implemented. A is credential authentication-gate requests (staff, API-key or widget/customer), conservatively defaulting to H (0≤A≤H). M is canonical-mutation decision requests, independently bounded0≤M≤H and also defaulting toH. Both summaries may occur on the same request. The default bound is therefore3H+64×C. Include retries and every additional composition explicitly. This is potential event capacity, not measured provider consumption, an owner allocation or a durable grant. Unknown workload bounds must be resolved before admission; integer overflow is rejected.

The memory-only collector samples every Nth validated event (default N=1), then retains at most64 events and16KiB of event JSON payload by default (hard configurable limits256/64KiB). Its wrapper and JavaScript heap are additional memory, not included in that payload count. Caller-held collector/snapshot references determine memory lifetime; no automatic persisted retention or secure-erasure guarantee exists. Dropped or sampled observations never refund the workload envelope or replace complete accounting. There is no remote retained-log store, exporter or live trace allocation in this local profile.

#64 must compose this envelope with domain work using `sumResourceEnvelopes` before admitting an enabled diagnostic workload, and reconcile through its durable authority rather than collector snapshots. Separate platform invocation logs, other application logs, export attempts/retries, provider-defined rounding and any D1/R2/other persistent export storage need additional envelopes under their actual resource dimensions. Persisted sampling/retention/access and verified provider boundaries remain gated by #42; the existing catalogue rates do not enable them. Canonical audit stays separate and unsampled.
