# Operational observability contract

Issue #159 adds a versioned, allowlisted runtime event envelope for active HTTP paths. It records a correlation ID, normalized route, method, outcome, status and latency only. The serialization boundary normalizes unknown routes/methods, validates UUID correlation IDs and finite nonnegative latency, derives outcome from a valid HTTP status, and drops every extra property. It does not accept arbitrary attributes and must never include authentication headers, cookies, OTP or magic-link material, API keys, channel credentials, provider payloads, ticket/article/attachment content, or AI prompts/outputs.

Canonical D1 audit remains the non-sampled evidence owned by #63. This diagnostic envelope is separate, can be sampled only under a later approved retention policy, and does not provide tenant analytics (#85) or customer diagnostic context (#92).

Local persistence is off. Emission requires `LOCAL_BETA_ENABLED=true`, `OBSERVABILITY_MODE=isolated-evidence`, and a non-production environment. Production is disabled pending #42 verification of access, retention, sampling and redaction. Telemetry failure is swallowed after the request outcome is set; it cannot bypass authentication, tenant isolation, durability, approval or recovery.

Initial SLI evidence is recorded as machine-readable JSON with revision, tool versions, environment, route class, request count, latency percentiles and failure counts. Do not ratify global thresholds from synthetic data. Preserve #51's separate measured 50 ms warm-ingress target. Tenant-composed D1 invocations and tenant-qualified attachment R2 calls now emit bounded operation envelopes in isolated evidence mode. Future hooks: pre-tenant/legacy-R2/DO operation envelopes, Workflow/AI fallback, and #87/#88 journal, Queue, outbox and dispatch states.

Alert runbooks must cover DLQ/quarantine, oldest pending journal/outbox age, dispatch uncertainty, sustained active-path errors and budget-admission failures. Include diagnostic event volume and retention in #50/#64 accounting before enabling any non-local evidence channel.

## Local performance receipt

From the repository root, run `npm run evidence:operational-performance --workspace=apps/server`. The harness creates and disposes a real local two-tenant Miniflare fixture, performs operator MFA, warms each scenario once, then measures20requests per scenario with concurrency2. Scenarios cover health, unauthenticated metadata denial and authenticated metadata reads. It accepts no remote URL or credentials. JSON contains exact Git revision/dirty state, harness source hashes, tool versions, configuration, nearest-rank latency percentiles, distinct response/failure counts, inventory and explicit limitations. Credentials and response bodies never enter the receipt.

`npm run test:operational-performance --workspace=apps/server` verifies deterministic clock/statistics, concurrency and input bounds. `npm run typecheck:operational-performance --workspace=apps/server` checks the harness. Its local baseline does not ratify production thresholds or complete canonical-write/resource/Queue/AI measurements. Stored D1row/R2object inventory is not billed-operation accounting.

## SLI definitions and collection status

These are the initial collection contracts, not ratified production promises. Use a five-minute operational window and a one-hour comparison window for rates; performance receipts also retain their exact bounded sample window. A zero denominator means **no observations**, never 100% availability. Record attempted/completed/failed counts separately so missing completions are visible. Percentiles use completed observations with the sample count and failure count alongside them; failure latency is not silently dropped. Unsampled audit remains separate.

| Path | Denominator and success numerator | Other observations and current collection status |
|---|---|---|
| API | Requests received / requests with an expected terminal outcome. Expected denials are distinguished from unexpected 5xx and transport failures. | Route-class latency and outcomes exist in the HTTP envelope; the local receipt checks explicit expected status for three scenarios. Fleet-wide aggregation is pending. |
| Authentication | Authentication attempts / correctly completed decisions; rejection rate is a separate signal, not automatically an availability failure. Correctness requires negative and revocation tests, not counting HTTP200. | Challenge, verification and rejection operation categories remain to instrument; no identifiers, submitted tokens or codes. |
| Canonical mutation | Authorized admitted mutation attempts / durable commits acknowledged successfully. Denied requests are reported separately and must not become successful writes. | Commit latency, failed attempts and uncertain acknowledgements remain to instrument. Retries count as attempts; stable operation accounting must distinguish duplicate replay from additional durable effects. |
| D1 | Database operations attempted / operations completed according to their explicit result contract. | Tenant-composed statement and batch latency/fulfilled-or-rejected outcomes are instrumented; metadata read/write counts, pre-tenant calls and complete transaction accounting remain pending. Stored-row inventory is not this denominator or billing count. |
| R2 | Storage operations attempted / expected operation results, including expected missing-object results where applicable. | Tenant-qualified attachment get/put/delete emit completion latency/outcome in isolated evidence mode. Legacy/unscoped R2 and aggregate bytes/complete operation accounting remain pending; never object names, keys, URLs or contents. |
| Durable Objects | Invocations attempted / expected completions. | Admission/rejection, latency and durable state-transition failures remain to instrument; no raw object IDs or state. |
| Workflows | Runs started / runs reaching their defined successful terminal state; terminal failures and still-running runs are separate. | Retry count, oldest active age and step failure category remain extension work. |
| AI fallback | AI-eligible attempts / correct completion through either AI or the approved fallback. | Provider failure and fallback rates are separate; a successful fallback must not hide provider degradation. Tokens/resource units use the cost contract; prompts and outputs are excluded. Instrumentation remains pending. |
| Journal / Queue | Authenticated accepted ingress operations / operations durably journaled before acknowledgement. Queue processing attempts / expected durable processing outcomes. | Pending age, retry, quarantine and DLQ counts extend #51/#91/#87; preserve #51's measured50ms warm-ingress SLO and its own scenario/percentile contract. |
| Outbox / dispatch | Durable eligible dispatch intents / intents reaching a verified terminal disposition. Attempts are separate from intents. | Oldest pending age, retries and uncertain delivery extend #88. Unknown provider acknowledgement is uncertainty, never assumed delivery. |

Do not derive tenant-qualified metrics from an untrusted request header or raw tenant ID. Where tenant correlation becomes necessary, add the governed pseudonymous reference and access/retention contract first. No resource instrumentation or aggregation is claimed by defining this table.

## Alert evaluation and response contracts

These conditions define required signals and response behavior. They do not enable external alerts, assume absent collectors are healthy, or ratify numeric global thresholds. Until a collector exists, report **not instrumented**. Thresholds needing a baseline stay explicitly unratified; production activation requires #42.

| Condition | Evaluation | Required response |
|---|---|---|
| DLQ or quarantine | Any newly entered item; retain current depth and oldest age, avoiding repeated notifications for the same unchanged state. | Inspect the protected recovery record with authorized tooling; identify the category, fix the cause and use the owning pipeline's bounded replay. Never log its payload or force acknowledgement. |
| Oldest pending journal/outbox age | Oldest eligible pending age exceeds that pipeline's approved recovery target. Exclude documented scheduled-not-before waits; separately show blocked/unknown states. No approved target means configuration incomplete. | Check dispatcher/consumer availability, admission and retry state. Preserve durable intent; do not delete old records to make the signal green. |
| Dispatch uncertainty | Any new uncertain provider outcome; unresolved age remains visible. | Reconcile using #88's provider/idempotency contract. Never blindly resend, mark delivered, or bypass approval because telemetry is inconclusive. |
| Sustained active-path errors | Unexpected failure numerator/attempt denominator in consecutive five-minute windows exceeds a baseline-ratified threshold, with the configured minimum sample count. Threshold/sample count are not yet ratified. | Compare the one-hour window and recent changes; verify auth and durability remain intact. Diagnose through safe categories and protected audit; do not disable those controls to restore a success rate. |
| Budget admission failures | Count intentional exhausted-budget denials separately from admission-service failures. Alert on a newly broken admission path; sustained denials use an approved tenant budget policy. | Check #50/#64 reservation/settlement and capacity state. Do not silently raise limits, spend paid capacity or fail open. |
| Missing telemetry | Expected collector heartbeat/receipt absent for its configured interval, or an invalid/incomplete receipt. | Report observability unavailable and investigate collection independently. Absence of telemetry does not prove service health or authorize state repair. |

Operational event volume, tracing samples and retained bytes belong in #50/#64 accounting. Current receipts run with telemetry off; there is no live retention, sampling budget or production alert channel to claim as configured. Environment configuration and resource hooks remain required #159 work.

## Scoped R2 evidence

The trusted tenant dependency factory supplies the observer to attachment storage only when the existing isolated local-beta evidence gate permits it. Upload admission still precedes the R2 call. Each composition emits at most64events; excess events are discarded, so this diagnostic stream is **not a complete cost counter or SLI denominator**. Durations cover the R2 API call, not subsequent streaming-body consumption. Missing objects are successful completed reads, not assertions that an attachment exists. No sampling changes audit or admission accounting.

`npm run test:tenant-isolation-storage-background --workspace=apps/server` includes real disposable Miniflare R2 measurement evidence with colliding tenant object names, own-byte reads, tenant A deletion and tenant B preservation. Six emitted envelopes contain only version/type/resource/operation/outcome/latency. The companion typecheck and focused adapter/helper tests cover production/off-mode suppression, the64-event ceiling, admission rejection before R2, sink failure and uncertain-write preservation. No external provider or production resource is involved. Other resource instrumentation and end-to-end operational acceptance remain #159 work.

## Scoped D1 invocation evidence

The trusted tenant factory supplies an observed D1 binding to its repositories, admission, policy, audit and replay dependencies only in isolated local evidence mode. Disabled mode returns the original binding. `first/all/raw/run` are classified as `d1/invoke`, since method names do not reliably identify SQL reads versus writes. `batch` is one measured call with original native statements and ordering; it is never decomposed or replayed. Native results and thrown errors retain identity. Fulfilled promise means completed invocation, not an independent assertion of commit/application success.

D1 and R2 share the same64-event composition ceiling. This remains incomplete diagnostic sampling, not cost accounting or a complete SLI denominator. No SQL, parameters, rows, error contents or tenant identifiers enter event envelopes. Pre-tenant auth/resolver calls, `exec/dump/withSession` paths and other resource families remain outside this measurement increment.

Focused wrapper/helper tests cover disabled identity, native receivers/chaining, batch unwrapping, result/error identity and privacy. Local Miniflare evidence verifies successful native batch execution, rollback of an earlier write when a later statement fails, raw/first results and actual trusted-composition local-mode emission/production suppression. All7storage/background tests and its typecheck pass; full pre-refreshserver447tests/typecheck and focusedlint pass. An initial composition edit accidentally touched a separate authentication resolver; runtime checks caught it, the unrelated resolver was restored, and final runtime/typechecks pass. No provider or production resource used.
