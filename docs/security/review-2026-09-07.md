# Application security review — 7 September 2026

**Review complete for the scope below; remediation remains open. This is not a clean
security result or approval for production/multi-tenant deployment.**

The PR containing this report changes development guidance/tooling, not application security behavior.

## Scope and methods

Source review traced HTTP authentication/authorization, customer and staff tickets,
attachments, API keys, inbound/outbound email, realtime notifications, knowledge/AI,
background indexing, automation/retention and provisioning defaults. It included the
D1 migrations, Worker bindings, application entrypoints, selected frontend rendering/auth
paths, dependency manifests and the checked-in CI workflow.

The baseline server suite passed: **27 files, 217 tests**. Additional private checks used
real service/handler code, two synthetic customers and SQLite in memory with all checked-in
migrations. External R2/email behavior was stubbed; no Cloudflare account, live customers,
production database, outbound email or paid AI was used. One concurrency check deliberately
synchronized two token reads to test an adverse interleaving. These checks establish specific
code behavior, not Cloudflare runtime equivalence or a penetration test of a live deployment.

The review reproduced security defects and confirmed some existing customer-ownership denials.
Detailed evidence, severity rationale and remediation instructions are delivered privately to
the maintainer in accordance with `SECURITY.md`. Do not copy unpatched reproductions to public
issues. No GitHub private advisory has been created by this review tooling.

## Dependency baseline

`npm audit --json` reported **20 affected package entries: 13 high, 4 moderate, 3 low**.
These counts include development tooling and transitive dependencies, not twenty demonstrated
application exploits. The lockfile needs remediation and reachability triage. Existing
Dependabot PRs cover several updates; coordinate them instead of opening duplicates.
The audit without development dependencies reported four affected entries (one high, three moderate); details were captured in the private report.
Do not run forced, unreviewed major-version upgrades simply to reduce the count.

## Release decision and follow-up

[Issue #13](https://github.com/nathcymru/Tocyn/issues/13) remains open for remediation and
regression evidence. Authentication, authorization/visibility, email trust, dependency and
operational findings must be triaged before an application release. Track detailed exploitable
findings privately, patch with regression tests, then coordinate disclosure.

[Issue #19](https://github.com/nathcymru/Tocyn/issues/19) remains open for implementation of
the [tenant-isolation gates](tenant-isolation-review.md). Current tenant readiness is **blocked**.

This review did not certify production configuration, email authentication at Cloudflare's
edge, distributed rate limits, load resistance, live secret rotation, backups/restores or
browser end-to-end security. The checkout was shallow; no full historical secret scan was
performed. GitHub scanning being enabled does not mean all its findings were assessed here.
Re-review changed security flows and validate in an isolated staging environment before release.

Repository-wide action SHA enforcement remains **deferred**, as requested, because of the
reported GitHub-managed workflow compatibility issue. New checked-in action references remain
pinned. That administrative exception is separate from application security remediation.
