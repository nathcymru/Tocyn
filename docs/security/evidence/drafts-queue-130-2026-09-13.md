## Contract

`GET /api/tickets?queue=drafts` requires an authenticated MFA operator whose JWT
actor/tenant/role match the verified scope before list admission. Repository reads
also require the viewer to match the verified operator scope. The correlated
predicate selects only the same tenant, current actor and ticket primary key from
operator_drafts. It does not read draft bodies. Existing ticket group visibility,
saved filters, sorting and pagination still refine the same count/page predicate.
API keys, customers, absent credentials and revoked sessions cannot use this
operator queue in the exercised real HTTP flow.

Expiry is filtered only when ENVIRONMENT is local and LOCAL_BETA_ENABLED is true,
matching the existing workspace service boundary. One server-generated ISO cutoff
is used by count and page; explicit expires_at or the existing legacy updated_at
plus48hours fallback must be greater than that cutoff. Other environments inherit
no new retention policy. Queue reads delete no drafts. A saved draft remains in
Drafts regardless of snooze/status unless existing explicit filters narrow it.

The dashboard adds a Drafts view and factual No saved drafts state. During a view
change it retains previous confirmed rows and Refreshing status but suppresses
new-queue inclusion claims until current data arrives. Queue captions use their
finite labels rather than the custom-view fallback.
