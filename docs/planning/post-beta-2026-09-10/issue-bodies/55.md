## Objective and dependencies

Tenant-owned Meta WhatsApp Cloud API support using the shared direct-message lifecycle. Parent [#49](https://github.com/nathcymru/Tocyn/issues/49); blocked on [#51](https://github.com/nathcymru/Tocyn/issues/51) and [#50](https://github.com/nathcymru/Tocyn/issues/50).

## Technical specification

- [ ] Guide tenant setup of app secret, webhook verification token, access token, WABA and phone-number ID. Encrypt credentials, validate account ownership and document token expiry/rotation and provider activation requirements. No central Embedded Signup integration in v1.
- [ ] GET registration verifies `hub.mode` and `hub.verify_token` before returning `hub.challenge`. POST validates `X-Hub-Signature-256` using HMAC-SHA256 over exact raw bytes and constant-time verification; match WABA/phone identity to connection.
- [ ] Iterate all `entry[] -> changes[] -> value` elements. Fan out `messages[]` and `statuses[]` independently; delivery acknowledgements must not create tickets. Mixed batches across conversations must preserve each event's identity.
- [ ] Map stable sender/WhatsApp IDs and `contacts` display metadata without automatically merging portal contacts. Preserve string IDs and media references; fetch text/image/media asynchronously via authenticated provider APIs into scoped R2.
- [ ] One active ticket per connection/direct sender; append bursts without fragmentation. Clearing the active mapping on resolve/close is atomic. Apply conservative gratitude handling only through the shared policy; unavailable AI creates normal new work.
- [ ] Store provider occurrence timestamp, edge receipt timestamp and processing timestamp separately. Update the latest legitimate inbound time monotonically using the provider message timestamp, never Queue processing time or delayed edge receipt. Reject/quarantine impossible timestamps rather than extending authority.
- [ ] Send free-form text and supported attachments only within 24 hours of the last customer message. Enforce in dashboard, server API and immediately before each dispatch/retry. Queue latency never extends Meta's window.
- [ ] On expiry, disable free-form composition and display a persistent explanation that the customer must message again. Preserve unsent drafts and record window-expired delivery status; do not repeatedly retry permanent window errors.
- [ ] Approved template sending is explicitly deferred. No automatic email fallback without independently verified email identity and a supported user-selected channel relationship. Do not claim a template sender inherently requires a large sync subsystem; deferral is a scope choice.

## Acceptance criteria

- [ ] Valid/invalid registration, tampered POST, wrong account and repeated event tests.
- [ ] Mixed multi-entry message/status batches create/append the correct tickets once; names do not establish cross-account identity.
- [ ] Text/image retrieval and failed-media states preserve message content and tenancy.
- [ ] Window tests at just below/exactly/above 24 hours, an eight-hour Queue delay, delayed delivery, out-of-order timestamps and retry crossing expiry.
- [ ] AI-off/cost-exhausted paths, concurrent first messages and close races behave as the shared contract specifies.
