## Objective and dependencies

Build the shared contracts before vendor plugins. Depends on the policy/authority interfaces in [#50](https://github.com/nathcymru/Tocyn/issues/50); parent [#49](https://github.com/nathcymru/Tocyn/issues/49). Decouple public webhook response time from ticket writes, media retrieval and AI. Tenant-owned apps are the v1 model.

## Ingress and plugin API

- [ ] Expose `/api/webhooks/{provider}/{tenant_id}/{connection_id}`. Tenant/connection path fields are routing hints; verify the stored app/account identity and cryptographic authority. Index `(tenant_id, connection_id)` lookups.
- [ ] Cache configuration in bounded isolate memory for at most 30 seconds from authoritative-fetch start, not response completion. No stale-on-error extension or KV refresh that resets the freshness clock. Cold isolates perform measured authoritative reads. Consumer writes and outbound dispatch recheck status/version.
- [ ] Preserve bounded exact bytes before parsing; never re-encode JSON before HMAC verification. Use Web Crypto verification or constant-time comparison with safe unequal-length handling. No plain shared-secret string equality.
- [ ] Handle registration challenges before normal ingestion using provider-specific authentication/response requirements. Valid normal requests return the provider's success response only after durable acceptance. Invalid signatures return 401 without queue or payload writes. Unknown/disabled connections fail closed; queue/storage failures return retryable failure.
- [ ] Strict admission consumes reserved credits; missing credits require replenishment or visible rejection. No optimistic unbudgeted enqueue.
- [ ] Define `IChannelPlugin` with `verifySignature(request, verificationContext): Promise<boolean>` and `normalizePayload(payload: unknown, context): NormalizedMessageEvent[]`. Verification context is typed for HMAC/JWT/header credentials; a single secret string is insufficient for all providers. Add separate challenge, acknowledgement and outbound methods. Bound raw-body reads and keep secrets out of public results.
- [ ] Provide versioned `RawWebhookEnvelope` with trusted connection/version, provider, ingress receipt time, request/event reference and raw payload reference. Persist only necessary headers; never authorization tokens or signing secrets.
- [ ] Define `NormalizedMessageEvent` with schema version, provider event/message IDs, trusted tenant/connection, kind (message/change/status/lifecycle), sender, channel/conversation/thread, content, attachment references, provider occurrence time and edge receipt time. Record processing time separately. All provider identifiers, including Slack timestamps, remain strings; parsing must not first lose numeric precision. Normalization fans out batches and can return zero supported events.

## Durable acceptance, persistence and dispatch

- [ ] Retain Queues as the ingestion backbone. Store bounded accepted raw envelopes in tenant-scoped R2 and queue compact pointers; maintain a recoverable pending-event journal before acknowledgement. Pending records let the sweeper recover lost publication or expired Queue deliveries. Never make Queue retention the only acknowledged-message recovery mechanism.
- [ ] Measure the added R2/journal cost in the SLO. Enforce the current Queue serialization limit with overhead and maximum raw payload size; reject oversized inputs explicitly, never truncate. Provider media is fetched asynchronously, not embedded as unrestricted base64.
- [ ] Use D1 event uniqueness and conditional/transactional writes for at-least-once, unordered delivery. Duplicate requests must not produce duplicate tickets/articles/outbound intents. Handle replies arriving before parents without detached duplicate tickets.
- [ ] Commit outbound intent with the ticket/article mutation in a D1 transaction. A dispatcher recovers unpublished outbox entries and uses provider adapters; attach stable delivery IDs. Record uncertain sends where provider idempotency/reconciliation is unavailable; never promise exactly-once external delivery.
- [ ] Configure per-message retries with bounded exponential backoff and DLQ. Poison schema/type errors enter quarantine without blocking the batch. DLQ/replay tooling checks current tenant/connection authority, preserves deduplication, records disposition and consumes reserved capacity. Free Queue retention is 24h; the durable pending journal must survive/recover that expiry. Delete raw payloads only after terminal processing and the explicit retention policy, not blindly while pending.
- [ ] Authenticate media retrieval, constrain provider endpoints/redirects and size/type, store under scoped R2 keys, and retain failure state without losing the message. Stored bodies/media are canonical; D1 holds metadata/references. Document indexed search capability rather than silently removing body search.
- [ ] Persist inbound content before optional Workers AI routing/sentiment. Apply cost policy, bounded input and schema-validated output. AI failure falls back to deterministic/manual triage. Gratitude classification sheds first.

## D1 design and credentials

Use composite tenant keys/FKs and scoped repositories:

| Table | Required responsibility |
|---|---|
| `channel_connections` | tenant/id, provider, external account/app IDs, enabled/revoked state, config version, nonsecret settings, timestamps |
| `channel_credentials` | tenant/connection, purpose/version, authenticated ciphertext, encryption-key ID, validity/revocation timestamps |
| `channel_identities` | tenant/connection/provider-account/sender identity, display metadata, optional explicitly verified contact link |
| `channel_conversations` | tenant/connection/conversation key, active ticket, last closed ticket/time, thread/group/topic references |
| `channel_events` | stable dedup key, kind, provider/receipt/processing times, object references, processing/version state |
| `channel_outbox` | stable intent ID, destination/connection, ticket/article reference, status, attempts, next retry, provider result |

- [ ] Encrypt credentials with authenticated encryption and bind tenant/connection/purpose as associated data. Keys live in Worker secrets. Version/rotate credentials; show only masked metadata in UI. Never put credentials in Queue messages, logs, manifests or static browser assets.
- [ ] Extend contact/ticket creation for external-only identities. Existing customer email constraints require an explicit migration and response/UI handling; no fake email and no implicit portal login. Names/phone numbers alone cannot merge identities.
- [ ] Check active connection/version in the authoritative write transaction/conditional SQL so a check-before-write race cannot revive revoked processing. Separate current revocation from a historically valid cached signature. Already-issued external requests cannot be recalled.

## Conversation policy

- [ ] Slack/Teams: each top-level human message in an explicitly configured support channel creates a ticket; replies append. Ignore bot/system echoes and deduplicate overlapping event subscriptions.
- [ ] Direct messages: one active ticket per tenant, connection and conversation/sender context. Enforce unique active mapping and atomic creation; `ON CONFLICT` recovery must reuse the winning ticket and avoid orphan ticket rows. Resolving/closing clears the mapping atomically and preserves last-closed reference.
- [ ] Group/topic context is part of the routing key; the same sender in private and group conversations must not collide. Preserve alias mappings for supported migrations.
- [ ] Within 24h of closure, narrowly identified gratitude-only text may append as an attributed note without reopening/alerting. Persist first; uncertainty, attachments, new requests, unsupported language or unavailable AI creates normal new-ticket work. Store decision metadata and provide agent recovery. Do not use sentiment positivity as gratitude or trust an uncalibrated self-reported model confidence.

- [ ] Tests cover raw whitespace/key order, malformed signatures, string IDs, batched messages/statuses, duplicate events, reordered replies, concurrent first messages and resolution races.
