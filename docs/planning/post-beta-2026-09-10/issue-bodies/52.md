## Objective and dependencies

Extend existing enterprise API capabilities; do not rebuild them. Parent [#49](https://github.com/nathcymru/Tocyn/issues/49); depends on [#51](https://github.com/nathcymru/Tocyn/issues/51) delivery contracts and [#50](https://github.com/nathcymru/Tocyn/issues/50) budgets.

Baseline already includes API-key hashing/resolution, dashboard key management, scoped permissions and ticket create/read/update routes. Existing automation webhook egress is restricted, but is not the reliable signed subscription/outbox system specified here.

## Technical specification

- [ ] Preserve existing `/api/v1/tickets` compatibility, hashed key storage, one-time secret display and tenant-scoped generation/revocation. Add explicit permission selection and lifecycle regression coverage.
- [ ] Publish OpenAPI schemas for create/read/update and errors. Validate payload size/content and reject wrong/expired/revoked keys with 401, valid keys lacking scope with 403.
- [ ] Add tenant/key-scoped idempotent creation: same key and payload returns the original result; conflicting reuse returns 409. Define expiry and prevent replays creating duplicates within the documented window.
- [ ] Replace per-isolate abuse controls with Cloudflare edge rate limiting plus cost-policy admission. Global strict quotas use authoritative reservations, not permissive edge counters. Return 429 for quota rejection with a documented reset hint.
- [ ] Add tenant-scoped webhook subscriptions, event selection, destination verification, delivery status and secret rotation. Tenant-chosen destinations require approved HTTPS egress policy; preserve SSRF/private-address/redirect protections and timeouts, never turn existing origin restrictions into unrestricted fetching.
- [ ] Record each outbound intent transactionally with the source mutation. Use shared Queue dispatcher, stable event/delivery IDs, tenant-specific HMAC over version/timestamp/exact body, key-version header and receiver verification example. Never expose signing secrets after setup except explicit rotation.
- [ ] Retry timeouts/network errors/429/5xx with bounded exponential backoff and provider `Retry-After` where applicable. Mark permanent failures terminal; provide operator replay and retain uncertain-send state. Every attempt consumes reserved budget.
- [ ] Document browser-independent API integration examples for monitoring/CRM tools; no dedicated Datadog/Sentry/RMM plugin is implied.

## Acceptance criteria

- [ ] Valid scoped keys create, read and update tickets; invalid/revoked keys fail; other-tenant IDs never leak data or mutate records.
- [ ] Concurrent idempotency replays create exactly one ticket; conflict and expiry contracts are tested.
- [ ] A mutation followed by Queue failure retains its outbox intent and recovers without duplicate intent creation.
- [ ] Receiver fixtures verify signature bytes/timestamps and secret rotation; tampered payloads fail verification.
- [ ] Test 429/5xx/backoff, poison destinations, redirects/private targets, retry exhaustion, replay, quota depletion and notification deduplication.
- [ ] Existing API clients/tests stay compatible; cost estimates and docs reflect actual operations.
