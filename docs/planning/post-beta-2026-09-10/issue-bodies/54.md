## Objective and dependencies

Two-way support in configured Teams channels, with a tenant-owned Entra/Azure Bot registration. Parent [#49](https://github.com/nathcymru/Tocyn/issues/49); blocked on [#51](https://github.com/nathcymru/Tocyn/issues/51) and [#50](https://github.com/nathcymru/Tocyn/issues/50).

## Technical specification

- [ ] Provide generated Teams manifest ZIP and guided Entra/Azure Bot setup, callback URL, app identifiers and encrypted credentials. Use a supported manifest/schema validated at implementation time; do not assert an unverified universal 1.25 requirement.
- [ ] Implement Worker-compatible Bot Connector activity handling using standard fetch/Web Crypto and reviewed JWT validation. Do not adopt the archived Bot Framework SDK. Document Azure registration prerequisites without moving Tocyn's runtime off Cloudflare.
- [ ] Validate JWT signature/JWKS, issuer, audience, expiry and applicable serviceUrl claim; cache public signing keys safely. No disabling validation. Bind verified Entra/app/account identity to Tocyn connection authority.
- [ ] Request `ChannelMessage.Read.Group` resource-specific consent in the manifest so messages in explicitly configured channels arrive without mentions. Missing consent is a visible setup failure, not silent partial capture.
- [ ] Normalize message Activities, preserving tenant/conversation/channel/activity IDs as strings. Extract Entra object identity where supplied; retain provider identity when absent, never invent email or infer authority from display name.
- [ ] Every top-level human message in configured support channels creates a ticket; replies append. Preserve conversation references and reply/activity IDs for proactive asynchronous agent replies.
- [ ] Refresh display metadata and conversation references only from authenticated supported activities. Renaming a tenant/team is not a change of immutable identity. Handle supported migration/update activities and retain mappings; never accept an arbitrary unverified replacement service URL.
- [ ] Keep Graph change-notification subscriptions out of v1. They use validation-token/clientState and, where applicable, richer notification validation—not a universal Teams HMAC signature. Do not mix this with Bot Connector JWT handling.
- [ ] Respect the actual activity response contract, not a blanket 202 or unsupported universal five-second assertion. Persist first, then acknowledge promptly and dispatch asynchronously.

## Acceptance criteria

- [ ] Test valid/wrong audience/issuer/tenant, expired JWTs, key rotation, forged service URLs and absent consent.
- [ ] Two tenants with overlapping display names cannot cross-route; unconfigured channels are excluded.
- [ ] Root/reply/dedup/reorder and proactive reply tests preserve original threads.
- [ ] Authenticated metadata/reference updates work without changing tenant authority; untrusted migration data is rejected.
- [ ] Workerd-compatible tests, rate-limit failures, budget exhaustion and revoked credentials preserve recoverability.
