## Objective and dependencies

Tenant-owned BotFather bots with private-chat and configured group/topic support. Parent [#49](https://github.com/nathcymru/Tocyn/issues/49); blocked on [#51](https://github.com/nathcymru/Tocyn/issues/51) and [#50](https://github.com/nathcymru/Tocyn/issues/50).

## Technical specification

- [ ] Guide BotFather token setup, validate bot identity with the provider and encrypt the token. Generate a separate high-entropy webhook secret; do not reuse the bot token.
- [ ] On explicit connection activation call `setWebhook` with callback URL, required update subscriptions and the `secret_token` parameter. Telegram then sends `X-Telegram-Bot-Api-Secret-Token`; it is not a client-supplied custom HTTP header in the registration call.
- [ ] Before intake, bound/check header format and use constant-time comparison with safe length handling. Missing/wrong header returns 401 without queue writes. Token-bearing API URLs must not enter logs.
- [ ] Deduplicate by connection/bot and `update_id`. Preserve user/chat/message/topic identifiers as strings without intermediate precision loss. Normalize supported messages and lifecycle events separately.
- [ ] Direct messages use one active ticket per connection/sender. Groups/topics are explicit allowlists with distinct conversation contexts; preserve `reply_to`/topic routing. Document privacy-mode/admin-permission requirements and do not claim receipt of messages Telegram does not deliver.
- [ ] Handle authenticated `migrate_to_chat_id`/`migrate_from_chat_id` updates atomically. Verify existing ownership, retain old/new aliases for delayed updates, avoid duplicate tickets, and never reassign another tenant's chat mapping.
- [ ] Send agent replies using the original chat/topic/reply references through shared dispatch. Handle token revocation, Telegram retry instructions and delivery uncertainty. Disabling a connection stops dispatch and controls webhook removal explicitly.

## Acceptance criteria

- [ ] Missing/invalid secrets return 401; malformed unequal-length inputs never throw or leak credentials.
- [ ] Repeated Updates produce one message; direct/group/topic conversations and tenants remain separate.
- [ ] Large/negative chat IDs round-trip exactly; group migration and delayed old-ID updates retain the same conversation.
- [ ] Agent replies return to the correct context; rate limits, revoked tokens, quotas and provider outages are tested.
