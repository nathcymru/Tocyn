# Workflow: pull request completion

After a PR is accepted/merged:

1. Verify the actual merged commit and required checks.
2. Determine whether the owning issue is fully complete or only advanced.
3. Add an issue receipt with:
   - PR and merge commit;
   - delivered behaviour;
   - validation evidence and limitations;
   - acceptance criteria completed/remaining;
   - progress percentage and rationale;
   - schedule effect/blockers.
4. Synchronize Project fields when permitted:
   - Status;
   - Progress %;
   - Forecast start/target if changed;
   - Actual start/completion where applicable;
   - Schedule variance.
5. If complete, set 100%, Done and Actual completion, then close the issue.
6. If partial, keep the issue open and leave a recoverable next action.
7. Reforecast dependent critical/near-critical work only when evidence materially changes timing.
8. If Project access is unavailable, include the intended updates in the receipt and report the limitation.

A merge is not automatically issue completion.
