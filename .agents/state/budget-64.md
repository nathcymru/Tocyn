# #64 budget coordinator foundation — 11 September 2026

This slice adds only a pure, JSON-serializable coordinator-state transition model at `apps/server/src/budgets/coordinator-state.ts`, with synthetic unit coverage. It binds durable state to one server-derived effective tenant policy; reservation requests cannot select a tenant, coordinator, allocation or owner policy.

The model provides all-or-nothing generic `ResourceAmounts` grants, deterministic coordinator-issued reservation IDs, holder binding, idempotency-envelope conflicts, separate new-work/recovery pools using the accepted policy split, durable warm-path decrement, revision fencing, expiry/lost-grant uncertainty, terminal-evidence reconciliation, and policy/restriction revision replacement. A grant ends at the earliest constituent interval boundary or the policy maximum lifetime. #50 defines `ResourceAmounts` as non-negative safe-integer units, which this model enforces without narrowing a fractional-unit contract. Composite identifiers reject control characters before they form internal keys, and the pure state holds at most 4,096 reservation records; it intentionally performs no record compaction in this foundation. Expired, lost, revoked and uncertain credits remain charged; consumed grants also remain charged after expiry. Nothing is reissued or given back a record slot merely because a lease expires. Reconciliation releases only a terminal-evidence-proven resource remainder. A measured overrun is retained as actual accounted usage, records a capacity defect and blocks new reservations instead of being clamped. Repeated identical evidence is idempotent while conflicting evidence is rejected.

The policy input is explicitly server-trusted by contract, not authenticated by this pure module. This is a tenant-allocation state machine only; it cannot safely apply a full owner/account ceiling independently to each tenant and must not be wired that way. `authorityCheckedAt` records the snapshot used for the transition; matching policy/restriction revisions only fence that snapshot and do not establish present authority freshness. A caller must revalidate membership/owner policy and apply revocations at its approved authority boundary before it creates another reservation. A later #64 slice must provide the separate `BudgetCoordinatorDO`, trusted current membership/owner-policy loading, atomic persistence/CAS that reserves the owner aggregate and tenant allocation together, authority freshness/revocation delivery, active-path envelopes, usage observation, durable evidence, reset integration and real concurrency tests. No bindings, migrations, active admission paths, provider work, remote resources or notifications are added here.
