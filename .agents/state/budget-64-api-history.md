# Budget #64 — API history admission

- Branch/worktree: `codex/64-api-history-admission` at the #196 storage baseline `55e7216`.
- Scope delivered: authenticated `GET /api/v1/tickets/:id/history` only. It preserves the existing tenant-scoped `tickets:read`, public-only, `limit` 1–50 and cursor response contract.
- Admission: each HTTP execution receives a fresh server operation ID; it is never a client-idempotent response replay. The fingerprint frames the API-history version, tenant, current API key, ticket and validated page. A pre-event-query tenant ticket lookup preserves 404 without capacity spend. Enabled admission rechecks the current integration key with `tickets:read`, then resolves policy/allocation authority through the bounded isolate grant path; malformed authority fails closed. Missing or `off` policy preserves the legacy route.
- Measured native evidence: migration 0043 backfills a tenant-scoped current-public-history projection and maintains it atomically across event insert/update/delete and article insert, visibility update and deletion. Miniflare D1/DO fixture seeds colliding tenant IDs, 51 public replies and their projection rows. A full page observes at most 102 D1 rows for the projection/event join, checks its tenant/ticket/sequence plan, uses one cold refresh/reservation, then uses a warm grant for a separately charged cursor request. A 3,000-event interleaved hidden/inaccessible prefix still returns the complete 50-event public page; visibility and deletion transitions remove their public events without cursor leakage. It checks invalid page, unknown ticket, exhausted capacity and a key revoked after API authentication all stop before the history query. The conservative business envelope is `workerRequests: 1`, `d1RowsRead: 2560`, and one request diagnostic envelope; isolate cold coordinator work remains separately prepaid.
- Remaining #64 API work deliberately not included: normal API ticket detail remains unbounded outside local beta because it lists all articles and resolves attachments; it needs its own pagination/response contract before admission. API PATCH has no durable idempotency receipt/fingerprint or atomic budget/write commit fence and must not be pre-spent until that canonical mutation seam exists. There is no API v1 ticket-list route in the current contract.
- Validation: `npm run typecheck --workspace=apps/server`; scoped server ESLint; targeted native history proof (5/5); conversation-audit native proof (9/9); CI-wired `npm run test:budget-admission-runtime` (100/100, 73.2s). Canonical create/reply metadata measured 133/125 D1 writes, respectively, under the unchanged 1,024 per-attempt ceiling. No remote resources, deployment, or provider billing used.
